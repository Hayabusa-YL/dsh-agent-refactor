## 为什么要做这个

现在大家都在用 AI 改代码。重构、迁移、删功能，agent 干得飞快。但有一个问题基本没人管：**清理**。

删掉一个功能之后，原来那个页面的组件文件没人 import 了，配套的 hooks、types、utils 也跟着晾在那；某个依赖装了但代码里再没引用过；两个模块互相 import 越缠越紧。人眼看不出来，linter 不管，测试也不会报——它只是默默地把项目撑大。

静态分析工具能告诉你"这个文件没有被引用"，但它不会告诉你**为什么**、**删了会不会炸**，更不会帮你**真的删掉**。

所以我把这三件事做进了一个工具：**查出来、给证据、安全地删掉，删坏了自动还原**。

## 它做什么

`agent-refactor` 是零配置的 JS/TS 项目体检工具，核心就两条命令：

```bash
npx dsh-agent-refactor scan   # 体检：死代码、未使用依赖、循环依赖
npx dsh-agent-refactor fix    # 一键清理：只删确认安全的项
```

### scan：每条结论都带证据链

不是甩你一句"orphan.js 未使用"，而是告诉你它是怎么被判死的：从入口出发不可达、0 处 import 引用、所有候选引用源逐一排除。出问题能顺着查，不用猜。

### fix：删之前先证明安全

这是它和"一键删除脚本"最大的区别。fix 的每一步都有闸门：

- 被删项必须先"引用了它的文件清单"为空；
- 删完立刻跑项目自己的测试门禁；
- 测试过了才落盘保留，**任何一步失败自动回滚到删除前**；
- 默认 dry-run，确认无误加 `--yes` 才真删。

### 一份可读的报告

scan 同时生成 HTML 报告，死代码、未用依赖、循环依赖分三档列出，每条附证据。

## 设计上的取舍（想清楚再抄）

1. **只做静态安全的部分**。它不碰有动态引用的文件、不猜字符串路径、不删你认为"肯定没用"的东西。查不到的，宁可不报。
2. **测试门禁就是唯一真理**。项目自己的测试过不了，它就不删。没有测试的项目，fix 只能 dry-run。
3. **零运行时依赖**，只有一个 yaml 做配置解析；单文件 CLI，`npx` 即用。
4. **不接入 LLM**。这一版全是确定性分析，删不删只看证据和测试结果。

## 快速上手

```bash
# 体检当前项目
npx dsh-agent-refactor scan

# 看清理计划，不写文件
npx dsh-agent-refactor fix

# 真删（会先跑测试门禁，失败回滚）
npx dsh-agent-refactor fix --yes
```

GitHub Actions 用户可以用仓库自带的 action.yml 一键接入 CI。
